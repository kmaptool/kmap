# 🗺 kmap

**kmap — программа для создания подробных и бесплатных карт, совместимых с любым
навигатором, смарт-часами и велокомпьютером Garmin.**

Карты создаются прямо на вашем компьютере за считанные минуты. Просто выберите страну или
регион, нажмите Build и скопируйте один файл `.img` на устройство. Карта готова к
использованию.

## Какую проблему решает kmap

Качественные карты для устройств Garmin обычно платные и редко обновляются. Программа
kmap позволяет вам самим создавать подробные карты любого региона или конкретной области
без лишних сложностей и длительного ожидания обработки данных, а также гибко настраивать
их под себя.

## Как работает программа

kmap использует данные [OpenStreetMap](https://www.openstreetmap.org) — бесплатной карты
мира, которую ежедневно обновляют добровольцы, добавляя малоизвестные тропы, родники,
беседки и укрытия от непогоды, часто отсутствующие даже на платных картах.

Сборка выполняется на вашем компьютере и для небольшого региона занимает пару минут.
Данные OpenStreetMap обновляются раз в сутки — просто пересоберите карту, когда она
понадобится.

kmap работает максимально быстро: используются все ядра процессора, загрузки идут
параллельно и возобновляются после обрыва связи, все скачанные данные кэшируются.
Повторная сборка того же региона начинается за секунды.

## Преимущества kmap

- Создание карт бесплатно и без подписок. Регистрация тоже не нужна.
- Высокая скорость работы. Создание карты занимает всего несколько минут.
- Безопасность пользователя. Программа работает на вашем компьютере (Windows, Mac или
  Linux) и никуда не передаёт персональные данные.
- Детальная кастомизация. Подробнее — в разделе [Что будет на карте](#что-будет-на-карте).
- Корректировка маршрутов. Автоматическое соединение близких разрывов дорог (до 5 метров),
  чтобы навигатор корректно прокладывал маршрут.
- Бесшовные карты. Можно выбрать несколько регионов или стран одновременно и объединить
  их в единую общую карту.
- Импорт стилей. kmap даёт возможность использовать визуальное оформление (TYP-файл)
  из доступных вам карт Garmin при создании новых карт. Подробнее — в разделе
  [Пользовательский стиль карты](#пользовательский-стиль-карты).

## 3 шага для создания собственной карты

1. **Установите kmap** — сборка для вашей системы [ниже](#установка).
2. **Запустите `kmap`**, выберите страну, регион или целый континент, нажмите **Build**.
   При первом запуске kmap предложит скачать несколько нужных ему инструментов. Вам нужно
   всего лишь нажать одну клавишу, остальное программа сделает сама.
3. **Скопируйте готовый файл** в папку `Garmin` на устройстве или на карте памяти.

> [!TIP]
> Не уверены, что всё настроено? `kmap doctor` проверит и подскажет, что именно изменить.

## Что будет на карте

- **Горизонтали** — тонкие линии высот, по которым туристы читают склоны, с шагом на ваш
  выбор.
- **Отмывка рельефа** — мягкие тени, благодаря которым горы выглядят горами, плюс профиль
  высот вашего маршрута.
- **Прокладка маршрутов** и **поиск** по адресу или названию.
- **Дневные и ночные цвета**, номера домов, береговая линия, точки интереса.
- **Подписи на местном языке**, по-английски или по-русски — как вам удобнее.

Каждую из этих функций можно включать или отключать в настройках перед сборкой. Уберите
то, что вам не нужно, — карта станет меньше и будет работать быстрее.

## Интерфейс и командная строка

Вы можете использовать kmap двумя способами: в полноэкранном интерфейсе TUI или из
командной строки для скриптов и автоматизации. Возможности одни и те же. Это руководство
показывает оба способа:

| 🖥 В интерфейсе                                               | ⌨️ В командной строке                         |
|---------------------------------------------------------------|----------------------------------------------|
| Запустите `kmap`                                              |                                              |
| Выберите регион                                               | укажите регион: `kmap build austria`         |
| Выберите профиль и настройте, что нужно именно для этой карты | `--profile="GPSMap 67"` и любые флаги поверх |
| Нажмите **Build** и следите за ходом сборки                   | тот же ход сборки, только в терминале        |

В обоих случаях готовая карта появится в `~/kmap` — остаётся скопировать её на
устройство.

## Пользовательский стиль карты

По умолчанию kmap рисует карты в стандартном оформлении OpenStreetMap или OpenTopoMap —
достаточно выбрать один из этих вариантов. Но это не все возможности. **Если у вас есть
карта, лицензия которой разрешает использовать её оформление, вы можете применить готовые
стили к новым картам.**

|                                       | 🖥 В интерфейсе                                                                                                                                                      | ⌨️ В командной строке |
|---------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------|---|
| **1 · Получите оформление из карты**  | Экран **Styles**, клавиша `i`, выберите `.img` или `.typ` — kmap также просматривает `~/Garmin` и подключённые устройства, так что файл на карте памяти найдётся сам | `kmap extract-typ моя-карта.img` |
| **2 · Восстановите стиль оформления** | Предлагается сразу после импорта — или откройте стиль и нажмите `r`, *recover from its map*. Получается TYP, которым можно собирать карту | `kmap recover моя-карта.img --attach` |
| **3 · Соберите карту**                | Выберите стиль на форме сборки                                                                                                                                       | `kmap build … --style=typ:моя-карта` |

Оформление карты Garmin хранится внутри неё самой, в небольшом файле (TYP). kmap позволяет
извлечь этот файл и использовать его при создании новой карты. Обычно ничего редактировать
не нужно.

### Восстановите стиль оформления

В TYP хранятся коды всех объектов, однако файл не содержит информации о том, какой код
какому объекту на конкретной карте соответствует. kmap автоматически сверяет геометрию
карты с данными OpenStreetMap. Результат хранится вместе с импортированным TYP, и каждая
следующая сборка с этим стилем будет выглядеть как оригинал или очень похоже.

Все операции со стилями выполняются на экране **Styles**. Вы можете создавать копии
существующих стилей, переименовывать их, назначать стилем по умолчанию и изменять любые
параметры — вплоть до попиксельного редактирования иконок.

## Профиль под каждое устройство

Для разных устройств Garmin может потребоваться отдельная версия одной и той же карты:
например, максимально подробная для навигатора, облегчённая для смарт-часов или без
ночной темы для велокомпьютера. Просто создайте отдельный **профиль** (сохранённый набор
настроек сборки) для каждого устройства.

В верхней части формы сборки отображается строка профиля. При выборе профиля настройки
заполнятся автоматически. Дальнейшие изменения параметров будут затрагивать исключительно
текущую сборку, не влияя на сохранённый профиль.

| 🖥 В интерфейсе                                                                               | ⌨️ В командной строке |
|-----------------------------------------------------------------------------------------------|---|
| Экран **Profiles**: `n` новый, `c` копия, `r` переименовать, `d` удалить, `m` сделать текущим | `kmap profiles new/copy/rename/delete/use <имя>` |
| Изменяйте поля профиля на его форме                                                           | `kmap profiles set <имя> --interval=25 --no-dem …` — те же флаги, что у `kmap build` |
| Посмотреть настройки профиля                                                                  | `kmap profiles` — список, `kmap profiles show <имя>` — один целиком |
| Выберите профиль в верхней строке формы сборки                                                | `kmap build … --profile="GPSMap 67"` |

## Покрытие

kmap использует то же дерево регионов, что и Geofabrik: континенты, страны и области
вплоть до отдельного штата или федерального округа. Для создания карты можно выбрать
любую страну целиком, только нужную область или сразу несколько регионов.

| 🖥 В интерфейсе | ⌨️ В командной строке                                                                                                                     |
|---|------------------------------------------------------------------------------------------------------------------------------------------|
| Перемещайтесь по дереву стрелками `→` и `←`, ищите через `/` | `kmap regions` — континенты, `kmap regions europe` — страны, `kmap regions germany` — регионы; всё остальное — поиск: `kmap regions alp` |
| Отметьте несколько регионов `пробелом` — они соберутся **одной бесшовной картой** | соедините id плюсом: `kmap build austria+switzerland`                                                                                    |

- **Результат делится на файлы несколькими способами.** Один файл, если хватает места на
  карте памяти; по файлу на регион или на страну; ровно `--parts=<n>` файлов примерно
  одинакового размера — см. `--split`.
- **Данные всегда свежие.** Geofabrik обновляет выгрузки раз в сутки. Всё скачанное
  кэшируется, а при пересборке kmap сверяет кэш с сервером: вышла новая выгрузка —
  скачает её сам, не вышла — возьмёт из кэша. Расширили карту — докачается только
  новое.

## Установка

Скачайте свежую сборку для своей системы со страницы [Releases](../../releases).

### Windows

Запустите установщик — `kmap-<версия>.exe`. kmap будет установлен в Program Files, на
рабочем столе появится ярлык. Windows 10 версии 1803 и новее.

Установщик не подписан, и при первом запуске SmartScreen покажет «Система Windows защитила
ваш компьютер». Нажмите **Подробнее**, затем **Выполнить в любом случае** — это нужно
сделать один раз.

### Linux

```sh
sudo apt install ./kmap_<версия>_<арх>.deb
```

Ubuntu 20.04, Debian 11 и выше; Intel или ARM. Так же работает и под WSL.

Для остальных дистрибутивов (Arch, Fedora, openSUSE и др.) есть `.tar.xz`: распакуйте
архив и положите `kmap` в каталог из `PATH`. Нужны только glibc, libcurl и zlib.

```sh
tar -xf kmap_<версия>_linux_<арх>.tar.xz
sudo install kmap*/kmap /usr/local/bin/
```

### macOS

Откройте `.dmg` и перетащите **kmap** в папку «Программы». Или скопируйте исполняемый файл
в любой каталог из `PATH`. Требуется macOS 13 или новее; одна универсальная сборка
работает и на Intel, и на Apple Silicon.

Бандл подписан ad-hoc и не нотаризован у Apple, поэтому Gatekeeper остановит его при первом
запуске: «Не удаётся открыть kmap, так как Apple не может проверить его на наличие
вредоносного ПО». Нужно только разрешить запуск:

- **macOS 13–14** — нажмите на **kmap** в «Программах» правой кнопкой, выберите
  **Открыть** и в диалоге снова **Открыть**.
- **macOS 15 и новее** — запустите двойным щелчком, закройте диалог, затем откройте
  **Системные настройки → Конфиденциальность и безопасность**, найдите строку
  *kmap заблокирован* и нажмите **Всё равно открыть**.
- **Из терминала**, в любой версии — снять карантинную метку и забыть:

  ```sh
  xattr -dr com.apple.quarantine /Applications/kmap.app
  ```

### Первый запуск

kmap скачает нужные инструменты — Java, компилятор карт mkgmap, при необходимости
pyhgtmap:

| 🖥 В интерфейсе | ⌨️ В командной строке |
|---|---|
| Экран **Toolchain** показывает, чего не хватает, и устанавливает это одной клавишей | `kmap install` |
| Там же — состояние каждого инструмента | `kmap doctor` |

### Из исходников

Swift 5.9 или новее и Git.

**macOS.** Xcode или только его инструменты командной строки:

```sh
xcode-select --install
git clone https://github.com/kmaptool/kmap.git && cd kmap
make install    # бинарник — в .build/release/kmap, копия — в /usr/local/bin
```

**Linux, в том числе WSL.** Установите Swift по инструкции на
[swift.org/install/linux](https://www.swift.org/install/linux/) — через `swiftly` или из
архива, — и заголовки zlib:

```sh
sudo apt install zlib1g-dev
git clone https://github.com/kmaptool/kmap.git && cd kmap
make install    # или make install PREFIX=~/.local
```

Стандартная библиотека Swift вшивается в бинарник статически: на другом компьютере Swift не
нужен.

**Windows.** Установите Swift по инструкции на
[swift.org/install/windows](https://www.swift.org/install/windows/) — она же объясняет,
какие компоненты Visual Studio нужны тулчейну. Затем:

```powershell
git clone https://github.com/kmaptool/kmap.git; cd kmap
swift build -c release
```

Результат — `.build\release\kmap.exe`; DLL рантайма Swift установщик тулчейна уже добавил
в `PATH`.

### Опции сборки

Сборка из командной строки делает только то, что ей сказали: всё, что не включено явно,
выключено. `--profile` включает всё, что хранит сохранённый профиль, а флаг поверх
него переопределяет одну конкретную настройку. Неизвестное значение — несуществующий
стиль, число вне диапазона — останавливает сборку, а не молча заменяется значением по
умолчанию.

## Полезно знать

**Невидимые швы между тайлами.** Карты Garmin собираются из тайлов, и на многих
устройствах стыки между тайлами видны как тонкие светлые полоски. В kmap есть небольшой
патч для mkgmap, который разрешает тайлам рисовать немного за своей рамкой
(`--overlap`, `--land-overlap`), — и швы исчезают. Ставится один раз с экрана Toolchain
или через `kmap install`; без него эти флаги просто ничего не делают, и карта собирается
обычным способом.

**Порядок отрисовки линий.** Устройство Garmin рисует линии в той последовательности, в
которой они записаны в карте. Без дополнительной обработки эта последовательность
совпадает с порядком поступления данных и не учитывает значимость объектов: река может
быть нарисована поверх дороги, под которой она проходит, а подъездная дорога — поверх
магистрали. Тот же патч mkgmap устраняет этот недостаток. При сборке kmap читает правила
дорог из выбранного стиля, присваивает каждому типу дороги ранг по её значимости и
записывает дороги в порядке возрастания ранга, поверх остальных линий. Механизм работает
с любым стилем, встроенным или импортированным, и не влияет на время сборки.

**Горизонтали и рельеф — разные вещи.** *Горизонтали* — нарисованные линии высот с
выбранным шагом. *Слой DEM* — то, что даёт отмывку рельефа и профиль высот. Можно
включить одно, другое или оба; данные для обоих скачиваются один раз.

**Кодовая страница — важно для нелатинских карт.** `--code-page` решает, какой алфавит
попадёт в карту: 1252 — западная Европа, 1251 — кириллица. Неверное значение
превращает местные названия в транслит. kmap сам подбирает нужную по региону; `auto`
оставляет этот выбор за ним.

**Дороги, не дотянутые в OSM.** Картографы иногда обрывают дорогу в шаге от той, к
которой она примыкает, и устройство не прокладывает маршрут через этот разрыв. С
`--repair-ends` kmap закрывает такие разрывы (до `--repair-radius` метров) и помечает
на карте красным пунктиром, что именно придётся пересечь, если на пути было препятствие:
бордюр, канава, прочее. Так видно, что соединение достроил kmap, а не нанёс картограф.
Через такое соединение маршрут прокладывается как через обычную дорогу.

**Номера домов — поиск, не подписи.** Устройства Garmin не рисуют номера на зданиях.
`--house-numbers` наполняет *поиск адреса*: на устройстве откройте *Куда? → Адреса*,
выберите город, улицу и номер дома. `kmap osm-scan` показывает, сколько объектов в
выгрузке содержат `addr:housenumber`, а `kmap verify` подтверждает, что в готовой карте
есть поисковый индекс.

**Описания на устройстве.** У объектов OSM часто есть `description` — как найти родник,
открыта ли изба. В формате Garmin для этого нет поля, поэтому kmap может перенести его в
карточку объекта (`--descriptions`), а с `--custom-pois` — записать `.gpi`, где каждая
такая заметка ищется в разделе Custom POIs.

**День и ночь.** В стиле карты две цветовые схемы — дневная и ночная, и устройство само
переключается между ними. Но не все устройства делают это хорошо: некоторые Garmin Edge не
поддерживают тёмную тему, а если карта её содержит, стиль отображается плохо. В этом случае
оставьте в карте только одну схему: поле **Theme** на форме сборки или `--theme=day` —
устройство всегда будет показывать дневную карту. Можно и наоборот, `--theme=night`: тогда
карта навсегда ночная.

**Язык интерфейса.** Интерфейс доступен на английском и русском — это первое поле в
настройках. На саму карту это не влияет: язык подписей на карте задаётся для каждой
сборки отдельно, через `--labels` и кодовую страницу.

**Где что лежит**

```text
~/.kmap/cache     скачанные данные карт и рельефа, переиспользуются между сборками
~/.kmap/styles    набор правил и исходники стилей
~/.kmap/typ       ваша библиотека TYP — импортированные и восстановленные стили
~/.kmap/logs      полный вывод каждой сборки
```

## Для разработчиков

Любую команду kmap можно вызывать из другой программы — на Python, Go, чём угодно, что
умеет запускать процесс и читать stdout. Добавьте флаг `--json` в любом месте аргументов:

```sh
kmap build austria --profile="GPSMap 67" --json
kmap regions alps --json
kmap doctor --json
```

**Что меняет `--json`.** Обычный текст не печатается вовсе, и stderr молчит: всё, что kmap
хочет сказать, идёт в stdout по одному объекту JSON на строку, в порядке событий. Ошибка
приходит событием `error`, а не текстом в stderr — у читателя одна история в одной форме.

**Контракт стрима.** У каждой строки есть три поля: `event` — тип события, `seq` — номер
начиная с 1 без пропусков (если номер перескочил, строка потеряна), `at` — время в RFC
3339, UTC. Первая строка `start` несёт `schema` — версию контракта. Новые поля могут
появляться в любой версии, читатель должен игнорировать незнакомые; `schema` растёт только
когда поле меняет смысл или исчезает.

| `event` | Когда                                           | Поля |
|---|-------------------------------------------------|---|
| `start` | первая строка                                   | `command`, `version`, `schema` |
| `stage` | этап сборки сменил состояние                    | `stage`, `status`, `title`, `detail` |
| `progress` | продвинулась полоса или этап сообщил, чем занят | `overall` — доля всей сборки 0…1; `stage` и `fraction` — доля этого этапа (отсутствует, пока у этапа нет процентов); `detail`. Последний `progress` удачной сборки — `overall: 1` |
| `log` | строка журнала                                  | `severity` (`debug`/`info`/`warn`/`error`), `kind` (`plain`/`step`/`ok`/`output`), `text`, `stage`, `fields` — те же факты, что в тексте, но данными |
| `result` | ответ команды                                   | `data` — см. ниже |
| `error` | команда не выполнена                            | `message`, `code` |
| `end` | последняя строка                                | `ok`, `code` — тот же, что код выхода процесса |

Этапы сборки: `preflight`, `download`, `elevation`, `elevationBuild`, `split`, `compile`,
`collect`; состояния: `pending`, `running`, `done`, `skipped`, `failed`. Этапы рельефа
идут параллельно нарезке, так что два `running` одновременно — норма.

**Коды выхода.** `0` — выполнено; `1` — ошибка во время работы; `2` — неправильные
аргументы: неизвестная команда, несуществующий стиль или профиль, число вне диапазона, не
установлены инструменты; `130` — сборку прервали. С `--json` тот же код повторяется в
`end`.

**Что лежит в `result.data`.** У `build` — `destination` (папка), `outputs` (массив
`{name, path, bytes}` — файлы, которые надо скопировать на устройство), `stages` (по
этапу: `id`, `status`, `seconds`, `peakBytes`) и `seconds`. У `regions` — `in` (id
открытого региона или `null`) и `regions`: `id`, `name`, `parent`, `downloadable`,
`subRegions`, `boxes`; чтобы обойти дерево, откройте каждый регион с `subRegions > 0`. У
`styles` — `styles`: `id`, `name`, `origin`, `familyID`. У `profiles` — `profiles`: `id`,
`name`, `current`, `choices` — тот же набор, что принимают флаги. У `doctor` — `ready` и
`tools` с `id`, `ready`, `installable`, `path`. У `verify` и `coverage` — отчёт по каждой
карте. Точную форму любой команды проще всего увидеть, запустив её один раз с `--json`.

**Примеры.** Читайте stdout построчно, не дожидаясь завершения процесса:

<details>
<summary><b>Python</b> — развернуть</summary>

```python
import json, subprocess

proc = subprocess.Popen(
    ["kmap", "build", "austria", "--profile=GPSMap 67", "--json"],
    stdout=subprocess.PIPE, text=True, encoding="utf-8")

for line in proc.stdout:
    event = json.loads(line)
    match event["event"]:
        case "progress":
            print(f"{event['overall']:.0%}  {event.get('detail', '')}")
        case "result":
            for out in event["data"]["outputs"]:
                print("built", out["path"])
        case "error":
            print("failed:", event["message"])

exit_code = proc.wait()
```

</details>

<details>
<summary><b>Go</b> — стандартной библиотеки достаточно</summary>

```go
package main

import (
	"bufio"
	"encoding/json"
	"fmt"
	"os/exec"
)

type event struct {
	Event   string  `json:"event"`
	Overall float64 `json:"overall"`
	Detail  string  `json:"detail"`
	Message string  `json:"message"`
	Data    struct {
		Outputs []struct {
			Path string `json:"path"`
		} `json:"outputs"`
	} `json:"data"`
}

func main() {
	cmd := exec.Command("kmap", "build", "austria", "--profile=GPSMap 67", "--json")
	stdout, _ := cmd.StdoutPipe()
	if err := cmd.Start(); err != nil {
		panic(err)
	}

	scanner := bufio.NewScanner(stdout)
	scanner.Buffer(make([]byte, 1<<20), 1<<20) // a result line can be long
	for scanner.Scan() {
		var ev event
		if err := json.Unmarshal(scanner.Bytes(), &ev); err != nil {
			continue
		}
		switch ev.Event {
		case "progress":
			fmt.Printf("%3.0f%%  %s\n", ev.Overall*100, ev.Detail)
		case "result":
			for _, out := range ev.Data.Outputs {
				fmt.Println("built", out.Path)
			}
		case "error":
			fmt.Println("failed:", ev.Message)
		}
	}

	if err := cmd.Wait(); err != nil {
		if exit, ok := err.(*exec.ExitError); ok {
			fmt.Println("exit code", exit.ExitCode())
		}
	}
}
```

<details>
<summary><b>C++</b> — с nlohmann/json; на Windows вместо <code>popen</code>/<code>pclose</code> — <code>_popen</code>/<code>_pclose</code></summary>

```cpp
#include <cstdio>
#include <iostream>
#include <string>
#include <nlohmann/json.hpp>

int main() {
    FILE* pipe = popen("kmap build austria --profile=\"GPSMap 67\" --json", "r");
    if (!pipe) return 1;

    char buffer[1 << 16];
    std::string line;
    while (fgets(buffer, sizeof buffer, pipe)) {
        line += buffer;
        if (line.back() != '\n') continue;   // a long line arrives in pieces
        auto ev = nlohmann::json::parse(line);
        line.clear();

        const std::string kind = ev["event"];
        if (kind == "progress") {
            std::cout << int(ev["overall"].get<double>() * 100) << "%  "
                      << ev.value("detail", "") << '\n';
        } else if (kind == "result") {
            for (auto& out : ev["data"]["outputs"])
                std::cout << "built " << out["path"].get<std::string>() << '\n';
        } else if (kind == "error") {
            std::cout << "failed: " << ev["message"].get<std::string>() << '\n';
        }
    }
    return pclose(pipe);   // the exit code: WEXITSTATUS on POSIX
}
```
